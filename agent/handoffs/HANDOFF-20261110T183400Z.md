# Handoff — TASK-016: Fill and stroke separation

**Date**: 2026-11-10T18:34:00Z
**Task**: TASK-016
**Status**: Completed and verified

## Implementation Summary

- **AST/parser**: added optional `stroke` and `width` to `Rectangle`, `Circle`,
  `Ellipse`, `Square`, `Triangle`, and `Polygon`; closed shape blocks now parse
  `stroke` and `width` alongside `fill`.
- **Validation**: fill is optional for closed shapes. `S006` is retained as a
  reserved stable code but no longer emitted. Optional stroke widths are
  validated (`S011`, `S007`), and stroke paint colors use `T001`/`T002`.
- **Lowering**: closed shapes resolve independent fill and stroke paint IDs;
  width defaults to `1px` when omitted.
- **Renderer**: fill and stroke are drawn independently and in deterministic
  order (fill first, then stroke).
- **IR**: geometry remains separate from `fill: Option<PaintId>` and
  `stroke: Option<Stroke { paint, style }>`; no structural refactor needed.
- **Decision** `docs/decisions/DECISION-013.md` records appearance semantics
  and the retirement of `S006` from active use.
- **Task document** `agent/tasks/TASK-016.md` was missing and created before
  implementation.
