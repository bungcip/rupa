# Handoff — TASK-014: Line and polyline primitives

**Date**: 2026-11-10T18:18:00Z
**Task**: TASK-014
**Status**: Completed and verified

## Implementation Summary

- **Lexer**: added the `stroke` keyword token/mapping; also fixed the missing
  `polyline` keyword mapping (the token existed but lexed as an identifier).
- **AST/parser**: added `Stroke`, `Line`, and `Polyline` nodes.
  - `line from (x, y) to (x, y)` with `stroke` and optional `width`
  - `polyline` with nested `points`, `stroke`, optional `width`
  - `stroke none` lowers to no visible stroke
- **Diagnostics**: added `S010` missing stroke, `S011` invalid stroke width,
  `S012` polyline with fewer than two points; reused `S003`, `S007`, `S008`.
- **IR**: added `Line`, `Polyline`, and `Stroke { paint, style }`.
  `ShapeNode.stroke` now carries both paint and style.
- **Lowering**: lines/polylines lower with paint-arena stroke resolution;
  default width is `1px`.
- **Renderer**: open paths are stroked with color/width/opacity/transform;
  fill and stroke render independently when both exist.
- **Decision** `docs/decisions/DECISION-011.md` records conventions and the
  partial advance toward TASK-016.
- **Task document** `agent/tasks/TASK-014.md` was missing and created before
  implementation.
