# Handoff — TASK-006: Rectangle and circle primitives

**Date**: 2026-11-10T17:32:00Z
**Task**: TASK-006
**Status**: Completed and verified

## Implementation Summary

- **AST** (`crates/rupa-syntax/src/ast.rs`)
  - `Rectangle.position`, `Rectangle.size`, `Circle.center`, and
    `Circle.radius` are now `Option` so missing required properties survive
    parsing and become semantic errors instead of being dropped or defaulted
    to `0.0`.
- **Parser** (`crates/rupa-syntax/src/parser.rs`)
  - Retains rectangles/circles with missing `at`, `center at`, `size`, or
    `radius`.
  - Accepts a leading `-` on dimension literals, so negative dimensions and
    coordinates parse and reach semantic validation.
  - Updated existing parser tests to the new optional AST fields.
- **Shape validation** (`crates/rupa-compiler/src/shapes.rs`)
  - `S001` non-positive rectangle width/height
  - `S002` non-positive circle radius
  - `S003` missing `at` / `center at`
  - `S004` missing rectangle `size`
  - `S005` missing circle `radius`
  - `S006` missing `fill`
  - `S007` non-pixel shape coordinate/dimension
  - Documents rectangle top-left and circle-center semantics. Negative
    coordinates remain valid.
- **IR** (`crates/rupa-ir/src/geometry.rs`)
  - Removed the duplicate `PaintId` definition; `ShapeNode` now uses the
    paint module's single `PaintId`.
  - Added tests for geometry/paint separation, rectangle top-left/size, and
    circle center/radius.
- **Decision** `docs/decisions/DECISION-003.md` records the representation,
  code mapping (`R200`–`R205` → `S001`–`S006`), negative literals, and pixel
  unit policy.
