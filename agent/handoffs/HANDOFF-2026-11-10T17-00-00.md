## Key Implementation Details

### Parser Architecture
- Recursive descent parser consuming tokens from lexer
- Handles indentation via Indent/Dedent tokens
- Produces AST with full span information for diagnostics
- Returns `Option<Document>` and collects diagnostics in `DiagnosticBag`

### Error Handling
- Syntax errors produce diagnostics with stable codes (P001, etc.)
- Errors include file location, message, and helpful suggestions
- Missing required tokens (string after document, color after background, path after export) now produce proper errors
- Semantic validation (required size, radius, etc.) deferred to compiler (TASK-005)

### AST Structure
- `Document` with name, size, background, export, children
- `Rectangle` with position, size, optional fill
- `Circle` with center, radius, optional fill
- `Dimension` with value, unit, span
- `Color` enum (Named, Hex, Rgb, Rgba)
- All nodes carry source `Span`

## Known Issues / Limitations

1. **Semantic validation deferred**: The parser accepts syntactically valid but semantically incomplete code (e.g., document without size, rectangle without size, circle without radius). These will be validated in TASK-005 (compiler semantic analysis).

2. **Fill is optional in parser**: Shapes without fill parse successfully with `fill: None`. This matches the specification where fill is optional.

3. **No expression parsing yet**: Coordinates and dimensions are parsed as simple dimension values. Full expression parsing (arithmetic, variables, function calls) is for later milestones.

4. **Debug test removed**: A temporary debug test (`test_parse_circle_debug`) was used during development and has been removed.
