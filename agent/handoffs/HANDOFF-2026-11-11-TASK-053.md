# Handoff — TASK-053: Diagnostic codes and suggestions

## Task ID

TASK-053 (Milestone 8 — LLM Authoring Experience)

## Implementation Summary

- Added a single-source diagnostic code catalog in `rupa_syntax::diagnostic`:
  - `CodeInfo { code, name, description }`
  - `codes::ALL` and `codes::describe(code)`
  - `diagnostic_codes!` macro generates every `codes::CONSTANT` plus `ALL`, so a code cannot be added without a description or catalog entry.
  - Existing aliases stay inside `codes` (`RESOURCE_NOT_FOUND`, `INVALID_RESOURCE`, `RESOURCE_DECODE_ERROR`, `MISSING_FONT`) and resolve to canonical entries.
- Added `suggest_keyword` with a curated alias table (`colour`/`color` → `fill`, `rect` → `rectangle`, `bg` → `background`, `centre` → `center`, `z_index` → `z-index`, etc.) and the existing Levenshtein fallback.
- `Diagnostic::with_suggestion` now uses `suggest_keyword`, so document/layer/parser unknown-keyword diagnostics benefit from aliases.
- `Parser::push_shape_unexpected` now emits `L006` with a suggestion for unknown identifiers instead of a generic `P001`; rectangle and circle now reuse it.
- Layer validation (`S019`) suggests the closest defined layer name.
- Expression validation (`S025`/`S026`) suggests the closest variable name in scope.
- Suggestions use sorted candidate lists for deterministic output.
