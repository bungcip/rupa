# Handoff — TASK-069: Remove `export`; CLI-determined output path

## Task ID
TASK-069 (Milestone 10)

## Completed Work
- `export` is no longer part of the language:
  - `ast::Document` no longer has an `export` field and the `Export` node is
    deleted, so nothing downstream can read an output path from source.
  - `Parser::parse_removed_export` consumes `export "<path>"` and emits the new
    stable diagnostic `P005` with a `--output` hint (mirrors the `P004` removal
    of the `document` wrapper).
  - `format_source` rejects `export` with `P005` instead of reordering it; the
    canonical document-setting order is now `size`, `background`, `seed`.
- Retired codes stay defined for stability and are never emitted: `C004`
  (missing export), `C006` (invalid export path), `C012` (duplicate export) are
  documented as legacy in `codes`.
- `ValidationOptions` is removed (its only purpose was overriding export
  validation). `compile_source(source, file_id)` and
  `Validator::validate`/`validate_source` now take no options; `benchmark.rs`
  and all tests were updated.
- `rupa render input.rupa` writes `input.png` in the **current working
  directory**; `--output` still overrides. `CliError::MissingOutput` is gone and
  `--output` help text is updated.
- Sources migrated: `examples/**` and `benchmarks/**` `.rupa` files, every
  inline test source, and `docs/language-reference.json` (keywords, example,
  `settings.required` now empty, defaults documented, canonical order and
  top-level lists without `export`).
- The `repair-invalid` benchmark task was retargeted: its starter now omits the
  circle radius (expects `S005`) instead of relying on the removed missing-export
  error, and all benchmark prompts dropped their "Export to ..." instructions.

## Follow-up landed in this commit
- Output-path extension validation was restored at the CLI level after the
  export check was removed: `CliError::NonPngOutput` rejects any `--output` that
  is not a `.png` path (case-insensitive) before reading or rendering, and the
  default `<stem>.png` path always passes. Documented in specification §21 and
  covered by three CLI tests (`.jpg` rejected, extensionless rejected, `.PNG`
  accepted).
