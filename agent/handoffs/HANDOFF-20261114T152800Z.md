# Handoff — TASK-099 (Interned strings and token migration)

- **Task**: TASK-099
- **Milestone**: M16 — Interned identifiers
- **Status**: Complete
- **Date**: 2026-11-14

## Completed Work

- Added `ustr = "1.1"` to the workspace and `rupa-syntax`.
- Added `crates/rupa-syntax/src/intern.rs`:
  - `IStr` newtype over `ustr::Ustr`;
  - `Clone`, `Copy`, `Deref<Target = str>`, `AsRef<str>`, `Borrow<str>`;
  - value-based equality/hash and plain-string `Display`/`Debug`;
  - manual `Serialize`/`Deserialize` as a plain JSON string (no backend serde
    feature);
  - dedup, conversion, serde, and size tests.
- Exported `IStr` from `rupa-syntax`.
- `TokenKind::Identifier` now stores `IStr`; `TokenKind::String` stores
  `Box<str>`.
- Lexer `scan_identifier` slices the source directly, so it no longer builds a
  temporary `String` per identifier. Equal identifiers share one interned
  payload; equal string literals keep separate `Box<str>` allocations.
- Adapted parser pattern matching, keeping AST fields as `String` until TASK-100.
- Updated size/allocation guardrails and DECISION-042 with the backend choice,
  retention trade-off, and measurements.

## Known Issues

- The global intern table retains identifiers for the process lifetime by
  design. Only identifiers and finite names are interned; unique payloads stay
  as `Box<str>`.
- AST name/string fields still use `String` until TASK-100, so parser-side
  allocation remains for those fields.
- The documented `Arc<str>` fallback is not compiled in while `ustr` is
  available.
