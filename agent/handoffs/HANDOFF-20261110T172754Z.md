## Implementation Summary

- `crates/rupa-compiler/src/document.rs`
  - `DocumentValidator` validates only document-level constructs (shape
    validation remains in `ShapeValidator`, removing duplicate diagnostics).
  - `ValidationOptions` supports a CLI output override; the override takes
    precedence over the `export` declaration.
  - Rules: missing size `C005`; non-positive/non-finite dimension `C003`;
    non-pixel document dimension `C007`; missing export without override
    `C004`; empty/non-`.png` effective export path `C006`.
  - Document coordinate system (top-left origin, X right, Y down) documented.
- `crates/rupa-compiler/src/validation.rs`
  - `Validator::validate_source` / `validate_source_with_options` tokenize,
    enforce exactly one `document` (`C001` missing, `C002` multiple), parse,
    then run document and shape validation. All errors are collected.
- `crates/rupa-syntax/src/diagnostic.rs`
  - Added stable codes `C005`, `C006`, `C007`; tested for stability.
- `crates/rupa-syntax/src/parser.rs`
  - Accept top-level `export "file.png"` as shown in specification §5
    (previously only indented exports were parsed).
- `crates/rupa-cli/src/main.rs`
  - `check` and `render` now use source-level validation; `render --output`
    supplies the validation override.
- `docs/decisions/DECISION-002.md` records the export policy, code mapping
  (`R100`–`R103` → `C001`–`C005`), and pixel-unit rule.
