# Handoff — TASK-101 (Optimize enum layout by measurement)

- **Task**: TASK-101
- **Milestone**: M17 — Enum layout and verification
- **Status**: Complete
- **Date**: 2026-11-14

## Completed Work

- Measured every `DocumentChild` payload and the `Fill`/`Expression` components.
  `Fill` (408 B) — not `Text` (1016 B) or `Path` (768 B) — was the dominant cost.
- Boxed `Fill.gradient` and `Fill.pattern`; `Fill` fell 408 -> 72 B.
- Boxed `Expression::Position`; `Expression` fell 152 -> 72 B.
- Did **not** box `DocumentChild::Text` or `Path`: after the `Fill` change the
  largest variant is the 712 B rectangle/ellipse/triangle, so boxing them would
  not reduce the 720 B enum and would add allocations for common nodes.
- Kept finite names (`blend`, filter `kind`, pattern `kind`) as `IStr`; closed
  enums would change diagnostics for unknown values or need a raw-name variant,
  with no size win.
- Added `tests/boxed_variants.rs` for gradient/pattern/position construction,
  serialization, and evaluation.
- Added permanent variant-size reporting and tightened size/allocation
  guardrails; updated DECISION-042.

## Results

| Item | Before | After |
|------|-------:|------:|
| `Fill` | 408 | 72 |
| `DocumentChild` | 1056 | **720** |
| Rectangle/Ellipse/Triangle | 1048 | 712 |
| `Text` | 1016 | 680 |
| `Path` | 768 | 432 |
| `LayerDefinition` | 704 | 368 |
| `Expression` | 152 | 72 |
| `Repeat` | 224 | 144 |
| `Variable` | 200 | 120 |

- `DocumentChild`: 1456 (TASK-097 baseline) -> 720 = **50.5% reduction**.
- Fixture parse: **271 allocations / 101,203 bytes** (from 278 / 109,651).
- Each boxed payload costs exactly one `Box::new` when that payload is present.
- Render benchmark, 40 alternating release runs on `examples/paints.rupa`:
  median 20.97 -> 20.94 ms (-0.17%), mean -0.9%; output PNG byte-identical.
- wasm release: 1,388,244 -> 1,400,685 bytes (+0.9%, within the 5% target).
