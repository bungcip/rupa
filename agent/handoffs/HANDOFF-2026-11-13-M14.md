# Handoff — Milestone 14 (playground editing experience)

*Date: 2026-11-13*

## What shipped

- **Syntax highlighting** in the playground editor: a coloured `<pre
  id="highlight">` behind a transparent-textarea editor. One `WORD_CLASSES` map
  (keyword / property / colour / literal) drives the classes; colours are
  limited to the ten names `rupa-compiler` accepts. `refreshEditor()` repaints
  gutter + highlight on edits, Tab-indent, and example loads.
- **`rupa_format`** in `crates/rupa-wasm`: safe `format_source_text` /
  `encode_format_frame` plus the C ABI `rupa_format(src_ptr, src_len)`. It reuses
  the render frame header, so the host parses and frees both results the same
  way; the body is the canonical `rupa fmt` text and failures return diagnostics
  with empty text. 8 tests in `crates/rupa-wasm/tests/format.rs`.
- **Format button** in the playground header: rewrites the buffer with the
  canonical layout, keeps the caret clamped, refreshes decorations, and
  re-renders. Unformattable sources are left alone with status `Cannot format`
  and the returned diagnostics.

## Gotchas for the next agent

- `playground/rupa_wasm.wasm` is a build artifact: run `bash playground/build.sh`
  after any Rust change, then reload the page (the browser caches `app.js`).
- Formatting is token-based, so syntactically broken but lexable sources are
  still formatted; the render pass reports them afterwards.
- The format frame and the render frame share one header
  (`[u32 total][u32 meta_len][meta JSON][body]`) and both are freed with
  `rupa_free_frame`; copy bytes out before the next call.
- Keep the highlighter word lists in sync with `KNOWN_KEYWORDS`
  (`crates/rupa-syntax/src/diagnostic.rs`) and `NAMED_COLORS`
  (`crates/rupa-compiler/src/paint.rs`).
- Run cargo with `CARGO_INCREMENTAL=0` on this UNC workspace.
