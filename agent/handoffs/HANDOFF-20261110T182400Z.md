## Implementation Summary

- **AST/parser**: added `Path` and `PathCommand` (`Start`, `LineTo`,
  `CurveTo`, `QuadTo`, `Close`) plus `DocumentChild::Path`.
  - `start at`, `line to`, `close` parse directly.
  - `curve to` requires an indented `control (c1) and (c2)` block.
  - `quad to` requires an indented `control (c)` block (chosen interpretation,
    documented in DECISION-012).
  - Optional `fill`, `stroke`, and `width`.
- **Diagnostics**: added `S013` for a path with no commands or not beginning
  with `start at`; reused `S007` and `S011`.
- **IR**: `Geometry::Path { commands }` with `MoveTo`, `LineTo`, `CubicTo`,
  `QuadTo`, and `Close`.
- **Lowering**: maps all commands, resolves optional fill/stroke paint, and
  defaults stroke width to `1px`.
- **Renderer**: builds tiny-skia paths for lines, cubic/quadratic Béziers, and
  close; fill and stroke render independently.
- **Decision** `docs/decisions/DECISION-012.md` records command semantics,
  quadratic control syntax, implicit fill closure, and transform origin.
- **Task document** `agent/tasks/TASK-015.md` was missing and created before
  implementation.

## Known Issues / Notes

- Quadratic `control (c)` syntax is an implementation interpretation because
  the specification only shows cubic controls.
- Filled open paths are implicitly closed by the fill rule; explicit `close`
  is recommended for stroked outlines.
- Stroke cap/join/dash remain defaults until TASK-018.
- Fill/stroke IR separation remains TASK-016; this task already uses the
  `Stroke { paint, style }` representation introduced in TASK-014.
