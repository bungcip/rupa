# Handoff — TASK-023: Nested layer composition

**Date**: 2026-11-10T19:55:00Z
**Task**: TASK-023
**Status**: Completed and verified

## Implementation Summary

- **Parser**: `layer` blocks now accept `place` blocks in addition to `size`
  and drawing primitives. Unexpected-child help mentions `place`.
- **IR**: `RootChild` was generalized to `CompositionChild`; root documents and
  `LayerDefinition` both store ordered `children: Vec<CompositionChild>`.
  `LayerDefinition::children_in_render_order()` reuses stable z-index ordering.
- **Validation**: nested instances are validated against every definition name,
  so forward references work and errors use the existing codes (`S019` unknown
  layer, `S003` missing position, `S020` invalid z-index, `S014` transform).
- **Lowering**: a shared `lower_composition_children` path preserves source
  interleaving of shapes and instances for root and nested children.
- **Renderer**: recursion through nested instances composes
  `enclosing_parent * instance.local_to_parent_transform(layer)` and multiplies
  opacity down the hierarchy. Each composition sorts its own children by
  z-index. A recursive definition returns `RenderError::CyclicLayer` rather than
  overflowing the stack.
- **Decision**: `docs/decisions/DECISION-020.md` records the representation,
  validation, rendering, cycle-guard, and clipping scope.
- **Task document**: `agent/tasks/TASK-023.md` created before implementation.
