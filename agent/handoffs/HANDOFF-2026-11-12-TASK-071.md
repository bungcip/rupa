# Handoff — TASK-071: Layer semantics update

## Task ID
TASK-071 (Milestone 10)

## Completed Work
- **Optional layer size**: `LayerDefinition.size` stays optional and lowering
  no longer errors with `S015`; an omitted size resolves to the document canvas
  (which itself defaults to `256px x 256px`). `MISSING_LAYER_SIZE` is marked
  legacy and is never emitted.
- **Background `fill` shorthand**: `ast::LayerDefinition.fill: Option<Fill>`
  stores a `fill` written directly inside a `layer` block. The parser routes it
  through `parse_fill`, so solid, gradient, and pattern paints all work, and a
  second `fill` reports the new `S036` (`DUPLICATE_LAYER_FILL`) pointing at the
  duplicate line.
- **Lowering**: the background fill becomes a rectangle covering
  `(0, 0)..(layer width, layer height)` prepended to the layer's children, so it
  paints before all other content and inherits the plane's clipping, raster
  mode, opacity, and blend behaviour.
- **Validation**: layer background paint is validated with the same paint
  checks as shape fills; layer size validation only runs when `size` exists.
- **Empty layers**: an empty layer is valid and lowers to a plane child with no
  content.
- **Single-use planes**: unchanged semantics from TASK-070 remain verified —
  `place` targets groups only (`S034`) and a nested `layer` declaration inside a
  layer block is rejected by the parser.
- **Fixtures/docs**: `docs/language-reference.json` describes the optional
  layer size and background fill; new `examples/layer-fill.rupa` demonstrates a
  gradient background, omitted size, and an empty layer.
