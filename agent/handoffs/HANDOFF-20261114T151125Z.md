# Handoff — TASK-098 (Compact source spans)

- **Task**: TASK-098

- **Status**: Complete

## Completed Work

- `FileId` is now `u32`; `Position` is `line: u32`, `column: u32`,
  `offset: u64`; `Span` is **40 bytes** (down from 56).
- Added `Position::new`, `Position::from_usize`, and `Position::offset_usize`
  as the checked host boundaries. Lexer line/column counters are `u32` and
  saturate instead of wrapping.
- Updated lexer construction and scan helpers, parser fallback spans, formatter
  byte-offset slicing, diagnostic rendering conversions, and compiler test
  helpers.
- Added span merge/display/from-usize/offset/layout tests and a UTF-8 lexer span
  test that verifies byte offsets vs character columns.
- Tightened size guardrails (`FileId <= 4`, `Position <= 16`, `Span <= 40`) and
  updated `DECISION-042`.
- Recorded that the registry is now online: TASK-099 should use `ustr` and keep
  `Arc<str>` as the documented fallback.
- No diagnostic code, message, help text, JSON value, render order, or golden
  image changed.

## Known Issues

- `u32` line/column counters saturate at `u32::MAX`. This prevents wrapping but
  is not reachable for practical source files; documented in `span.rs` and the
  lexer.
- The wasm release module grew by 8,072 bytes versus TASK-097. TASK-102 will
  verify the final size budget.
