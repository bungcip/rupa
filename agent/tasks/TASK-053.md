# TASK-053: Diagnostic codes and suggestions

**Milestone**: 8 — LLM Authoring Experience
**Dependencies**: TASK-004
**Status**: Complete

## Goal

Ensure all diagnostic codes are stable, documented, and accompanied by actionable suggestions for common mistakes (including inside shapes, layer placements, and variable references).

## Scope

- Add a documented catalog of stable diagnostic codes (`codes::ALL` and `codes::describe`) in `rupa-syntax`.
- Expand keyword suggestions with a curated alias table (e.g. `colour`/`color` → `fill`, `rect` → `rectangle`, `bg` → `background`).
- Attach "did you mean" suggestions for unknown properties inside shapes and placements.
- Attach "did you mean" suggestions for unknown layer references (`S019`) and unknown variable references (`S025`).
- Add unit tests covering catalog completeness, code stability, and suggestions across syntax and compiler diagnostics.

## Acceptance Criteria

- [x] Every diagnostic code constant in `rupa_syntax::diagnostic::codes` is stable and has a description in the catalog
- [x] Unknown properties inside shapes and placements include `did you mean` suggestions when close to a valid keyword or common alias
- [x] Unknown layer and variable diagnostics suggest close matches defined in the document/scope
- [x] `cargo fmt -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo build --workspace`, and `cargo test --workspace` pass

## Implementation Notes

- Codes and the catalog are generated by one `diagnostic_codes!` macro invocation, so a code cannot be added without a description and catalog entry. Aliases (`RESOURCE_NOT_FOUND`, `INVALID_RESOURCE`, `RESOURCE_DECODE_ERROR`, `MISSING_FONT`) remain inside `codes` and resolve to canonical entries.
- `suggest_keyword` first checks a curated alias table, then falls back to the existing Levenshtein `did_you_mean` search.
- `Parser::push_shape_unexpected` now emits `L006` with a suggestion for unknown identifiers instead of a generic `P001`; rectangle and circle reuse it so every primitive gets consistent suggestions.
- Layers suggest close definition names; expression validation suggests close variable names already in scope. Suggestions are sorted for determinism.
